## 1. 총평

지문 대기는 "PAM 이 묻기 전에는 칸을 숨기고, 첫 프롬프트에 칸을 꺼낸다" 는 한 가지 규칙으로
서 있고, 그 규칙이 코드·문서·시험에서 같은 말을 한다. 취소 경로는 Esc·창 닫기·백스톱·polkitd
취소 넷이 모두 헬퍼 채널을 끊는 것으로 끝나며, 늦게 온 지문 매치가 권한을 주는 구멍은 §22-2 의
`poll()` 전환으로 막혔다. 비밀번호가 데몬을 지나지 않는 구조도 그대로다.

이번 리뷰에서 **권한 누출이나 자격 증명 노출로 확인된 결함은 없다.** 아래 발견은 이식성(fork
헬퍼가 살아 있는 배포판), 아주 짧은 경합 창, 그리고 두 모듈이 PAM 파일을 서로 다르게 읽는
불일치에 관한 것이다.

| 영역 | 판정 | 요지 |
|---|:---:|---|
| 취소 경합 (Esc / 닫기 / 백스톱 / polkitd) | 양호 | 네 경로 모두 채널을 끊는다. SIGTERM 경로만 Drop 을 건너뛴다 (F-1) |
| 비밀 취급 | 양호 | 보관 비밀번호는 echo-off 에만, 원시 쓰기, 자식 fd 격리 |
| 단계 전환 | 양호 | 첫 프롬프트가 유일한 계기. 전제가 깨지는 PAM 구성은 찾지 못했다 |
| PAM 파일 읽기 | 불일치 | `attempts` 는 include 를 따라가고 `fingerprint` 는 안 따라간다 (F-3) |
| 호출자 시계 | 양호 | 줄이기만 한다. systemd 문법과 어긋나는 입력은 모두 보수적 방향 |
| 시험 | 대체로 양호 | SIGTERM 취소와 include 된 pam_fprintd 는 가짜 헬퍼가 재현하지 않는다 (§4) |

## 2. 확인한 것 — 경로별

### 2-1. 취소가 헬퍼를 끊는가

- **Esc / 창 닫기** ([`gui.rs:629-634`](../src/gui.rs#L629-L634) → [`gui.rs:451-455`](../src/gui.rs#L451-L455)):
  `FromUi::Cancel` 을 보내고 창을 닫는다. 워커는 지문 대기 중이면 [`helper.rs:240-242`](../src/helper.rs#L240-L242)

  Cancel 을 받아 `Outcome::Cancelled` 로 돌아가고, `Channel` 이 drop 되며 소켓이 닫히거나 fork
  자식이 `kill` 된다 ([`helper.rs:208-215`](../src/helper.rs#L208-L215)). **확인함.**
- **백스톱** ([`gui.rs:457-464`](../src/gui.rs#L457-L464)): `Phase::Password` 에서만 돈다. 지문 단계는
  `None`. 문서(fingerprint.md §7)와 일치. **확인함.**
- **polkitd 취소** ([`agent.rs:298-322`](../src/agent.rs#L298-L322)): pidfd 로 SIGTERM. 자식에는 시그널
  핸들러가 없으므로 (`grep SIGTERM src/` 는 agent.rs 뿐) 기본 동작으로 즉시 죽는다. 종료 코드는
  `None` → `EXIT_CANCELLED` 로 접힌다 ([`agent.rs:383-384`](../src/agent.rs#L383-L384)) — D-Bus 쪽은
  맞다. 소켓 헬퍼는 커널이 fd 를 닫으므로 다음 읽기·쓰기에서 안다. **확인함.** 단 F-1.
- **호출자 포기 → polkitd 취소** 는 위와 같은 경로. 실측 §23-3.

### 2-2. 늦은 지문 매치가 권한을 주는가

`attempt()` 는 취소를 보면 채널을 drop 하고 돌아간다. 소켓 헬퍼는 우리 쪽 fd 가 닫힌 뒤
`pam_fprintd` 가 끝나 다음 쓰기를 할 때 EPIPE/EOF 를 보고 죽는다. 그 사이 매치가 나도 헬퍼가
`AuthenticationAgentResponse2` 를 보낼 쿠키의 세션은 자식이 exit 2 로 끝난 순간 사라졌다 (§22-5).
**확인함** (코드) + **실측됨** (§22-5). 단 헬퍼가 죽기 전까지 센서를 쥐는 것은 여전하다 — 열린
결정 (fingerprint-work-state 3번).

## 3. 발견

심각도: 권한 누출 > 자격 증명 노출 > 오동작 > 문구·문서. 이번 리뷰에 앞 둘은 없다.

### F-1. polkitd 취소(SIGTERM)는 fork 헬퍼를 고아로 남긴다 — 오동작 (이식성) · **확인함 · 고침 (rationale §22-7)**

- [`agent.rs:307`](../src/agent.rs#L307) 이 자식에 SIGTERM 을 보내고, 자식에는 핸들러가 없어 즉시 죽는다.
  `Channel::drop` ([`helper.rs:208-215`](../src/helper.rs#L208-L215)) 이 실행되지 않으므로 fork 헬퍼의
  `kill` 이 없다. 소켓 헬퍼는 커널이 fd 를 닫아 주지만, fork 헬퍼(`polkit-agent-helper-1` 자식)는
  PAM 이 끝날 때까지 산다 — `pam_fprintd` 30초 동안 센서를 쥔다.
- 재현: setuid 헬퍼가 있는 배포판(Debian·Fedora)에서 소켓 헬퍼가 없거나 실패하게 한 뒤, run0 로
  창을 띄우고 25초를 기다린다. 취소 뒤에도 `pgrep -f polkit-agent-helper-1` 이 남는다.
- 이 머신에서는 fork 가 죽은 코드라 재현되지 않는다 (§2-1 memory). 권한은 새지 않는다 — 쿠키
  세션이 끝났다.
- 고친 모양: 자식이 SIGTERM 을 플래그로 받아 Esc 와 같은 취소 경로를 타고, 에이전트는 2초 뒤
  남아 있으면 SIGKILL 로 올린다. 처음 적었던 `PR_SET_PDEATHSIG` 는 setuid exec 에서 커널이
  지우므로 쓸 수 없었다.

### F-2. 취소가 pidfd 등록 전에 오면 창이 남는다 — 오동작 (경합, 마이크로초) · **확인함 · 고침 (rationale §22-7)**

- [`agent.rs:340-374`](../src/agent.rs#L340-L374): spawn 뒤 `running` 에 넣기까지의 틈. 그 사이 온
  `CancelAuthentication` 은 `running` 에서 못 찾고 `remember_cancelled` 로 가는데
  ([`agent.rs:316-318`](../src/agent.rs#L316-L318)), `begin_authentication` 은 이미
  [`agent.rs:249`](../src/agent.rs#L249) 의 검사를 지났다. 자식은 끝까지 돈다.
- 결과: polkitd 가 버린 요청의 창이 남는다. 비밀번호 단계면 30초 백스톱, 지문 단계면 백스톱이
  없어 Esc 나 `pam_fprintd` 타임아웃 뒤 프롬프트 → 백스톱까지 산다. 답을 넣어도 쿠키 세션이 없어
  권한은 나오지 않는다.
- 틈이 spawn 직후 수 마이크로초라 실제로 맞추기 어렵다. §20-4 의 동시 요청 실측(req2·req3)에서도
  나오지 않았다.
- 고친 모양: `ask()` 가 pidfd 를 등록한 직후 마커를 한 번 더 소비하고, 있으면 SIGTERM 과 2초 뒤
  SIGKILL 승격.

### F-3. `fingerprint::configured()` 는 include 를 따라가지 않는다 — 오동작 (구성 의존) · **확인함 · 고침 (rationale §22-7)**

- [`fingerprint.rs:53-62`](../src/fingerprint.rs#L53-L62) 는 `/etc/pam.d/polkit-1` 또는
  `/usr/lib/pam.d/polkit-1` 의 **그 파일** 에서만 `pam_fprintd.so` 를 찾는다. 같은 프로세스의
  [`attempts.rs:215-262`](../src/attempts.rs#L215-L262) 는 `include` 를 따라간다.
- `pam_fprintd` 가 `system-auth` 나 `system-login` 같은 include 대상에 있는 구성(Arch 위키가
  권하는 방식 중 하나)에서는 `fingerprint_wait=false` 로 창이 칸을 보인 채 열리고, PAM 은 센서를
  기다린다. 사용자가 비밀번호를 치면 `cancelled()` 가 `pending` 에 보관했다가 지문 타임아웃 뒤
  첫 프롬프트에 답한다 — 동작은 하지만 30초 동안 "Checking..." 이 뜬다.
- Omarchy 는 `polkit-1` 파일 자체에 넣으므로 이 머신에서는 안 난다.
- 고친 모양: 읽기를 `src/pam.rs` 의 `auth_stack_names` 하나로 합치고 두 모듈이 모듈 이름만
  다르게 부른다.

### F-4. `Failed` 가 "오답" 이 아닌 경우에도 `Wrong password` 를 그린다 — 문구 · **확인함 · 고침 (rationale §22-7)**

- [`helper.rs:271-274`](../src/helper.rs#L271-L274): 답을 헬퍼에 쓰지 못하면 (`EPIPE` 등) `Outcome::Failed`.
  [`prompt.rs:117-126`](../src/prompt.rs#L117-L126) 은 `Failed` 를 오답으로 보고 `WRONG_PASSWORD` 를
  띄우고 예산을 다시 읽는다. 직전에 `conv.error("cannot answer the helper: …")` 도 갔으므로 창에는
  둘 중 나중 것인 `Wrong password` 가 남는다.
- 실제로는 헬퍼가 사라진 것이고 재시도는 새 헬퍼로 가므로 동작은 맞다. 문구만 틀리다.
- 고친 모양: 새 변형 `Outcome::HelperGone`. 재시도는 하되 `Wrong` 도 예산 재읽기도 없다.

### F-5. 리뷰 4a — 비밀번호 단계에서 지문 재시도 잡음이 `Wrong password` 를 덮는다 — 문구 · **확인함 · 고침 (rationale §22-7)**

- 오답 뒤 새 헬퍼는 `pam_fprintd` 부터 돈다. 그때 오는 `PAM_ERROR_MSG`(`Failed to match fingerprint`
  등)는 [`gui.rs:386-397`](../src/gui.rs#L386-L397) 에서 notice 를 덮는다. `PAM_TEXT_INFO` 는
  [`gui.rs:375`](../src/gui.rs#L375) 가 걸러 주지만 ERROR 는 안 거른다.
- 고친 모양: `Conversation::pam_error` 로 PAM 의 문구와 우리 오류를 갈라 보내고, 창은 오답부터
  다음 프롬프트까지 PAM 의 문구만 지운다 (`pam_muted`).

### F-6. `faillock`·`date` 를 PATH 로 찾는다 — 하드닝 · **확인함 · 고침 (rationale §22-8)**

- 처음에는 자식의 PATH 가 `/usr/local/sbin:/usr/local/bin:/usr/bin` 이라 위험이 낮다고 적었는데,
  그것은 시스템 매니저의 값이었다. 사용자 매니저의 PATH 는 `~/.local/bin` 과 mise shims 를
  `/usr/bin` 앞에 둔다 — 같은 uid 가 쓸 수 있는 자리다. 고친 모양: `date` 는 `libc` 의
  `strptime`/`mktime` 으로 대체, `faillock` 은 `/usr/bin`·`/usr/sbin` 절대 경로 + stdin null,
  가짜 faillock 은 디버그 전용 `SUDO_POP_FAILLOCK_BIN` 으로만. 시나리오 6 은 debug 바이너리로
  옮기고 릴리스에 그 문자열이 없는 것을 확인한다.

### F-7. 잠긴 계정은 지문도 시도하지 못한다 — 설계 관찰 · **확인함**

- [`prompt.rs:167-173`](../src/prompt.rs#L167-L173) 은 창을 열기 전에 거절한다. 그런데 stock Arch +
  Omarchy 지문 구성에서는 `pam_fprintd sufficient` 가 `pam_faillock preauth` 보다 앞이라, PAM 자체는
  잠긴 계정의 **지문** 을 받는다. 우리는 그 기회를 주지 않는다.
- 예산을 아끼려는 §4-1 의 의도와 맞고, 지문으로 잠금을 우회하게 두는 것이 옳은지는 별개 문제다.
  바꿀 것을 권하지는 않는다. 문서에 한 줄 있으면 좋겠다.

## 5. 설계 의견 (결정된 것과 겹치지 않는 범위)

- **F-1 은 이식성 문제로 분류하되 고칠 가치가 있다.** `PR_SET_PDEATHSIG` 한 줄이면 fork 헬퍼가
  부모와 함께 죽고, 이 머신의 동작은 바뀌지 않는다.
- **F-3 은 코드 중복이 낳은 불일치다.** 두 모듈이 PAM 파일을 읽는 함수를 하나로 합치면 사라진다.
- 취소 뒤 센서 30초 점유(열린 결정 3번)는 이번 리뷰 범위 밖이지만, F-1 을 고치면 fork 경로에서는
  자연히 사라지고 소켓 경로만 남는다는 점을 적어 둔다.

## 6. 결론

기능은 문서가 말하는 대로 동작하고, 이번 주의 실측(§22-6, §23, §24, §25, §26)이 코드의 전제를
뒤집은 곳은 §24 의 faillock 하나였고 그것은 이미 고쳐졌다. 남은 발견 일곱 중 이 머신에서
재현되는 것은 F-4·F-5 의 문구뿐이며, 나머지는 다른 배포판이나 다른 PAM 구성에서의 이야기다.
코드는 손대지 않았다.
