# 인증 창의 명령 표시와 실제 작업 사이의 불일치 위험

- 조사일: 2026-09-28
- 상태: 표시 개선 구현 완료 — 실제 실행 무결성 보증은 범위 밖

## 수정 전 확인한 사실

[`src/invocation.rs`](../src/invocation.rs)의 `command_of`는 요청 PID의 UID를 확인한 뒤 `/proc/<pid>/cmdline`을 읽는다. 명령은 최대 120자로 줄이고 인자를 공백으로 연결한다. 이는 인자 경계를 온전히 보존하는 표현이 아니다.

명령 표시가 있으면 `org.freedesktop.systemd1.manage-units`의 일반 목적 문구를 숨긴다. 코드 주석에서도 `/proc`의 UID 확인을 독립적인 보안 경계로 보지 않는다.

## 위험과 전제

- 요청 프로세스는 자신의 명령행 메모리를 변경할 수 있다. 표시 문자열이 실제 systemd 요청 내용을 증명하지는 않는다.
- 긴 명령에서 중요한 뒷부분이 잘릴 수 있다.
- 스크립트 이름을 보여 주더라도 실제 내용과 이후 실행할 동작까지 검증하지 않는다.
- 프로세스 종료·PID 재사용과 읽기 시점 차이도 표시 정확성에 영향을 줄 수 있다.

공격자가 사용자의 세션에서 정상적인 권한 요청을 발생시킬 수 있다면 사용자가 승인 대상을 오인하도록 만들 가능성이 있다. 이것은 PAM 검증 우회가 아니라 사용자에게 제시되는 승인 정보의 신뢰성 문제다.

## 기존 방어와 한계

[`src/agent.rs`](../src/agent.rs)는 인증 시작 요청이 polkitd에서 왔는지 확인한다. 이는 위조된 D-Bus 호출을 막지만 정상 polkit 요청을 일으킨 프로그램이 선의라는 보장은 아니다. 읽을 수 없는 명령은 추측하지 않고 표시를 생략한다.

## 개선 방향

- 긴 명령 전체와 인자 경계를 확인할 방법을 제공한다.
- 요청 프로그램, polkit action, 실제 승인 대상에 대한 정보를 구분해 표시한다.
- 요청자가 바꿀 수 있는 문자열은 참고 정보로 취급한다.
- systemd/polkit이 제공하는 작업 정보와 표시를 연결할 수 있는 범위를 조사한다. 표시 확장만으로 실행 내용의 무결성이 확보됐다고 주장하지 않는다.

## 완료 검증

긴 명령, 공백·개행이 포함된 인자, 변경된 argv, 종료된 요청 프로세스, 스크립트 실행 사례를 테스트한다. 권한을 얻는 동작과 UI 표시가 어떤 수준까지 일치하는지 문서화한다.

## 2026-09-28 적용한 개선

- 요청 명령을 요약과 전체 수집 정보로 분리했다. 상세 보기에서 전체 명령·polkit action·설명을 확인한다.
- 빈 인자와 인자 경계를 보존하고, 제어문자·방향 제어문자·잘못된 UTF-8을 이스케이프한다.
- 명령 수집 상한은 16 KiB·256개 인자이며, 상한 초과를 명시한다. 상세 보기에서도 숨기지 않는다.
- `manage-units` 작업 설명을 유지한다. 명령을 읽지 못하면 확인 불가로 표시한다.
- 명령행은 실제 실행이 검증된 정보가 아니라는 한계를 UI와 README에 명시했다.
- 상세 보기 열기/닫기와 긴 명령 표시, 입력·지문 피드백 회귀 테스트를 추가/유지했다.

요청자가 argv를 바꾸거나 스크립트 내용을 바꾸는 문제, PID 재사용 시 동일 UID의 다른
프로세스를 읽을 가능성은 남는다. 실제 승인 오인 공격을 재현하거나 원천 차단한 것은 아니다.
상세 보기는 인증을 멈추지 않으므로 지문 센서에 손가락을 대기 전에 내용을 검토해야 한다.
구체적인 동작과 검증은 [구현 문서](../docs/request-display-and-run0.md)에 기록했다.

후속 UI 보완: 별도 버튼 대신 생략된 명령에 돋보기를 표시한다. 짧은 명령도 명령줄 클릭으로
상세 보기를 열 수 있다. 호버에 따른 영역 변화와 반복적인 창 크기 요청을 막는 회귀 테스트를 추가했다.
