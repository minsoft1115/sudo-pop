# 비밀번호 입력 위젯의 평문 복사본 관리

- 조사일: 2026-09-28
- 상태: 구현 완료 — 앱 입력 훅 이후의 egui 평문 복사 경로 차단. 외부 입력 계층 및 보호 실패 정책은 아래 한계 참조
- 대상: sudo-pop 0.2.1-spike 작업 트리, egui 0.36.1

## 수정 전 확인한 사실

[`src/secret.rs`](../src/secret.rs)의 `Secret`은 비밀번호 버퍼를 `mlock`으로 잠그고 사용 후 `zeroize`로 지운다. 그러나 [`src/gui.rs`](../src/gui.rs)의 `draw_password_phase`는 이 버퍼를 일반 `egui::TextEdit`에 전달한다.

사용 중인 egui 0.36.1의 `text_edit/builder.rs`는 입력 처리 전후에 다음 형태로 실행 취소 기록을 갱신한다. 이 경로에는 비밀번호 모드를 제외하는 조건이 없다.

```rust
state.undoer.lock().feed_state(
    ui.input(|i| i.time),
    &(cursor_range, text.as_str().to_owned()),
);
```

`text_edit/state.rs`의 실행 취소 기록은 `(CCursorRange, String)`을 사용한다. 따라서 비밀번호 표시를 가리는 `.password(true)`만으로 평문 복사본 생성까지 막지는 못한다.

## 위험과 전제

주 버퍼 밖에 생긴 복사본은 우리 `Secret`의 잠금·삭제 대상이 아니다. 주 버퍼를 지웠더라도 프로세스 메모리에 평문이 남을 수 있고, 해당 페이지가 스왑으로 나갈 가능성도 있다. 실제 스왑 기록 여부와 외부에서 읽을 수 있는지는 OS 보호와 공격자의 권한에 따라 달라진다.

소스 확인만으로 원격 유출이나 무인증 권한 상승이 입증된 것은 아니다. 입력 이벤트, 붙여넣기, IME 경로의 추가 복사본도 별도 검토가 필요하다. `mlock`만으로 최대절전 이미지까지 보호된다고 보장할 수도 없다.

## 기존 방어와 한계

[`src/harden.rs`](../src/harden.rs)는 `PR_SET_DUMPABLE=0`과 코어 덤프 크기 제한을 설정한다. 인증 창은 별도 단기 프로세스로 실행된다. 이 방어는 메모리 노출 가능성과 시간을 줄이지만 모든 평문 복사본의 삭제를 보장하지 않는다. 보호 설정이나 `mlock` 실패 시에는 경고 후 계속 진행한다.

## 개선 방향

- 비밀번호 위젯의 실행 취소 기록과 일반 문자열 복사 경로를 제거하거나 비밀정보용 입력 구현으로 교체한다.
- 입력 이벤트·IME·클립보드까지 포함해 비밀번호의 생성, 복사, 해제 경로를 추적한다.
- 보호 설정 실패를 허용할지 정책을 명시한다.

## 완료 검증

실제 비밀번호 대신 테스트 문자열로 입력·삭제·재입력·전송·취소를 검증한다. 주 버퍼뿐 아니라 위젯 상태와 실행 취소 기록에도 평문이 보관되지 않는지 확인한다. 프로세스 종료만으로 삭제를 보장했다고 판단하지 않는다.

## 2026-09-28 적용한 수정

- [`src/secure_input.rs`](../src/secure_input.rs)를 추가했다. `raw_input_hook`에서 일반 입력·붙여넣기·IME 조합/확정 문자열을 잠긴 `Secret`으로 옮기고 원래 문자열을 `zeroize`한다. egui에 전달할 이벤트에는 문자 수만 같은 임시 식별자를 넣는다.
- `TextEdit`에는 숨김 입력의 평문을 노출하지 않는 `TextBuffer`를 전달한다. 실행 취소 기록, 변경 전 텍스트, 레이아웃과 복제된 입력 이벤트에는 마스킹 문자 또는 식별자만 들어간다.
- 위젯이 삽입을 요청하면 식별자를 보호된 입력으로 해석한다. 무시되거나 소비되지 않은 입력도 버퍼 해제 시 지운다. 창이 가려져 같은 raw input이 재전달되는 경우도 처리한다.
- 실행 취소·다시 실행은 비활성화했다. 문자 단위 커서 이동, 선택, 삭제, 붙여넣기, IME 조합/확정은 유지한다. 단어 이동·삭제는 실제 비밀번호의 공백 대신 마스킹 문자열을 기준으로 동작한다.
- 문자 삭제는 UTF-8 경계를 보존하면서 제자리에서 수행하고 남는 꼬리 바이트를 지운다. 최대 256자 제한으로 보호 버퍼가 재할당되지 않게 한다.
- 여러 `Secret`이 같은 메모리 페이지를 공유할 때 한 버퍼 해제가 다른 버퍼의 잠금까지 풀지 않도록 페이지 잠금을 참조 횟수로 관리한다.
- PAM이 명시적으로 요청한 echo-on 입력은 화면 표시가 필요한 비밀이 아닌 정보로 취급한다. 숨김/표시 모드 전환 시 기존 입력과 대기 입력을 지워 비밀번호가 표시되는 것을 막는다.

## 검증한 범위

`cargo test --offline --quiet`: 단위 테스트 150개와 통합 테스트 15개, 총 165개 통과. `cargo fmt --check`와 `git diff --check`도 통과했다.

실제 egui 프레임으로 한글·이모지 입력, 커서 이동·삭제, 붙여넣기, 전체 선택·잘라내기, IME 조합 교체·확정·취소, 길이 제한을 검증한다. raw event가 식별자로 치환되고, 위젯의 실행 취소 기록에 마스킹 문자만 남으며, 비밀번호를 클립보드로 출력하지 않는지 확인한다.

별도 테스트로 재전달된 raw input, 알 수 없는/이미 소비한 식별자, 숨김→표시 전환, 삭제한 메모리의 0 덮어쓰기, 버퍼 주소 유지, 공유 페이지 잠금 관리를 확인한다. 테스트 문자열만 사용하며 실제 비밀번호나 실제 스왑 유출은 시험하지 않았다.

## 남는 한계

- OS, IME, 클립보드, winit/egui-winit 등 raw-input 훅 이전 계층의 복사본은 이번 수정 범위 밖이다. 원래 클립보드 내용도 지우지 않는다.
- 모든 레지스터·스택·입력 장치까지 포함한 평문 완전 제거를 보장하지 않는다.
- `mlock`이나 프로세스 하드닝 실패 시 경고 후 계속 진행하는 정책은 유지했다. 최대절전 이미지 보호도 별도 시스템 정책이다.
- 실제 데스크톱 IME 및 지문 장치를 이용한 인증 시험은 자동 egui 테스트와 별개다.
- 나머지 이슈의 PAM, polkit 캐시, 배포 경로, sudo fallback 정책은 변경하지 않았다.

## 테스트 시나리오 보완

추가 검토 후 실제 `Window::raw_input_hook`의 포커스 상실·복귀, Enter 제출, 인증 대기 중 입력 거절, 재시도를 테스트했다. 긴 IME 조합과 입력 한도 경계의 연속 이벤트를 정식 회귀 테스트에 편입하고, 실제 커널 메모리 잠금도 확인한다. 전체 Cargo 테스트는 169개가 통과했다.

새 `tests/input-scenario.sh`는 실제 GUI에서 공백·한글·이모지·Backspace 편집과 오답 후 재입력을 가짜 helper와 연결해 정확한 문자열 전달을 검증한다. 2개 시나리오가 통과했다. 실제 계정 인증이나 faillock 초기화는 하지 않는다. 기존 전체 시나리오는 최신 빌드와 PASS/FAIL/SKIP 구분을 적용하고, faillock 초기화를 제거했다. 실행 범위와 남은 수동 검증은 [테스트 안내](../tests/README.md)에 기록했다.
