# 사용자 영역 인증 프로그램의 변조와 가짜 팝업 위험

- 조사일: 2026-09-28
- 상태: 위협 모델·배포 방식 검토 필요 — 실제 변조는 수행하지 않음

## 확인한 사실

현재 설치 방식은 사용자 홈에 바이너리와 셸 래퍼를 둔다.

- `~/.local/bin/sudo-pop`
- `~/.local/lib/sudo-pop/bin/sudo`
- `~/.config/minsoft1115/bash/sudo-pop.sh`

[`src/init.rs`](../src/init.rs)와 [`install.sh`](../install.sh)가 이 배포를 관리한다. sudo-pop은 사용자 세션의 polkit 인증 에이전트이며 자체 setuid 프로그램으로 설치되지 않는다.

## 위험과 전제

같은 사용자 권한으로 이미 실행 중인 악성 프로그램은 사용자 소유 파일이나 시작 설정을 변경할 수 있다. 다음 인증에서 변조된 프로그램이 실행되면 비밀번호를 탈취하거나 다른 작업의 승인을 유도할 수 있다. 별도로 인증 창을 흉내 내는 피싱도 고려해야 한다.

이는 무인증 원격 접근만으로 성립하는 공격을 뜻하지 않는다. 사용자 세션에서의 코드 실행과 이후 사용자의 입력·승인 등이 필요한 시나리오다. 그러나 사용자 권한 침해와 관리자 권한 획득은 다른 단계이므로 이 경로를 무시할 수는 없다.

## 기존 방어와 한계

polkitd 발신자 검증은 정상 프로그램이 위조 D-Bus 요청을 받는 경우를 방어한다. 이미 프로그램 자체가 바뀌었거나 가짜 창이 별도로 표시되는 경우까지 막지는 못한다. 프로세스 디버깅 차단도 디스크의 사용자 소유 실행 파일을 보호하지 않는다.

## 개선 방향

- 바이너리를 관리자 소유의 시스템 경로에 패키지로 설치하는 선택지를 검토한다.
- 업데이트 출처·무결성 및 사용자 서비스와 시작 설정의 변조 가능성을 함께 검토한다.
- 관리자 소유 바이너리만으로 가짜 창이나 세션 전체 침해까지 해결된다고 주장하지 않는다.
- 신뢰할 수 있는 인증 UI를 위해 데스크톱에서 제공할 수 있는 구분 수단을 조사한다.

## 완료 검증

격리된 테스트 환경에서 파일·상위 디렉터리·서비스 설정의 소유권과 쓰기 권한을 확인한다. 배포 방식별로 같은 UID의 공격자가 변경 가능한 영역과 남는 위험을 정리한다. 실제 사용자 바이너리를 변조하는 시험은 하지 않는다.
